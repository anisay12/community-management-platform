# Lot L2 — Design system and navigation (bilingual EN/FR) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use beads-superpowers:subagent-driven-development (recommended) or beads-superpowers:executing-plans to implement this plan task-by-task. Steps within tasks use checkbox (`- [ ]`) syntax for human readability.

**Goal:** Every page of the application uses one accessible, token-driven Bootstrap 5.3 design system with a role-adapted navigation (desktop top bar, mobile side menu), a reusable component library, light and dark modes, and automated axe-core accessibility checks in CI. The read-only audit log pages (plan `2026-10-09-l2-audit-log-page.md`, already implemented on this branch) move onto the design system and get their open review nits fixed.

**Architecture:** Front-end sources live in `src/core/static/core/scss/` and are compiled with Dart Sass from pinned npm dev dependencies (`package.json` + `package-lock.json` at the repository root). The compiled, vendored output (`src/core/static/core/dist/`) is **committed**, because the development Compose stack mounts `./src` read-only over the image (an image-time build would be shadowed) and because it keeps Node out of the Docker image; `make assets-check` (CI) fails when the committed output is stale. Templates: `base.html` (application layout with navigation), `base_minimal.html` (sign-in and error pages without the navigation), components in `src/core/templates/components/`. The navigation is a registry in `core/navigation.py` that later packages extend. No JavaScript framework: Bootstrap's bundle (offcanvas, dropdown, toast, modal, tabs) and HTMX 2, both served as local static files.

**Tech Stack:** Django 5.2 LTS, Python 3.13, uv, Bootstrap 5.3.8 (Sass), Bootstrap Icons 1.13.2, HTMX 2.0.11, Dart Sass 1.105.1, axe-core 4.14.0, pytest-playwright (Chromium), PostgreSQL 16.

**Source spec:** `.internal/specs/2026-10-09-mvp-knowledge-design.md` § 5 "Work package L2 — Design system and navigation"; framing § 8 row L2 (acceptance: full keyboard navigation; AA contrast verified with axe-core in CI); framing risk D4 (charter missing → tokens in one file).

## Decisions taken in this plan (defaults)

- **Navigation shows only destinations that exist.** The spec's MVP navigation lists Communities, Resources, Events, Lessons learned, Search and Notifications; their pages arrive in L3–L9. To respect "no fake empty screen", the registry declares each entry with the URL name it needs, and an entry is shown only when that URL resolves *and* the viewer is allowed; today that means Home, Administration (user management), Audit log, the profile menu (My profile, Preferences, My data, Sign out) and the language switcher. Each later package registers its entry.
- **Compiled assets are committed** (see Architecture), regenerated by `make assets`.
- **No Talan logo or charter is invented**: `brand/logo.svg` is a neutral placeholder with the text "Communities" / « Communautés » next to it; all brand values are tokens in `tokens.scss`.
- The community card component is built now as a pure presentational template taking plain arguments (L3 will pass real communities).

## Global Constraints

- Language of code, comments, docstrings, commit messages, docs: **English**. UI bilingual EN/FR: every user-facing string goes through `gettext`/`gettext_lazy`/`{% translate %}`/`{% blocktranslate %}`. After adding strings run `cd src && uv run python ../manage.py makemessages -l fr --no-location --no-obsolete --ignore=.venv --settings=config.settings.test` and fill **every** new French entry in `src/locale/fr/LC_MESSAGES/django.po` in natural French (no untranslated, no fuzzy — `make i18n-check`). `.mo` files are not committed.
- **No behaviour change** to authorization, authentication, MFA, forms, services or URLs while restyling: every existing test keeps passing unchanged, except assertions on markup that this plan deliberately changes (update those assertions; never weaken an authorization or security assertion).
- Accessibility (WCAG 2.1 AA): exactly one `h1` per page; landmarks `header`, `nav` (each with a distinct `aria-label`), `main#main`, `footer`; a skip link as the first focusable element; visible focus on every interactive element (a 3px focus ring token, never `outline: none` without replacement); AA contrast in **both** colour modes; touch targets ≥ 44×44 px (links in navigation, buttons, form controls, pagination); form fields keep `<label for>`, help text and errors linked with `aria-describedby`; icons are decorative (`aria-hidden="true"`) unless they are the only content, in which case they get a visually hidden label.
- Tokens: all brand values are CSS custom properties prefixed `--tl-` declared in `src/core/static/core/scss/tokens.scss`, which also feeds the Bootstrap Sass variables, so changing the charter means editing that one file. Minimum token set: `--tl-color-primary`, `--tl-color-primary-contrast`, `--tl-color-secondary`, `--tl-color-success`, `--tl-color-warning`, `--tl-color-danger`, `--tl-color-info`, `--tl-color-bg`, `--tl-color-surface`, `--tl-color-text`, `--tl-color-text-muted`, `--tl-color-border`, `--tl-color-focus`, `--tl-font-sans`, `--tl-font-mono`, `--tl-radius`, `--tl-space-unit`, `--tl-touch-target` (44px), with a dark set applied under `@media (prefers-color-scheme: dark)` (Bootstrap `$color-mode-type: media-query`). Light mode by default.
- Static files: referenced only through `{% static %}`; no CDN, no external font or script. JavaScript files loaded with `defer`. No inline `<script>`/`style` attributes beyond what already exists (keeps a future CSP simple), except the static 500 page which must stay self-contained.
- Pinned versions exactly: `bootstrap 5.3.8`, `bootstrap-icons 1.13.2`, `htmx.org 2.0.11`, `sass 1.105.1`, `axe-core 4.14.0` (npm, `devDependencies`, exact versions, `package-lock.json` committed). Python: `pytest-playwright` added to the dev dependency group with `uv add --dev`, `uv.lock` updated.
- HTMX: loaded on every page of `base.html`; CSRF keeps going through `hx-headers` on `<body>` (already present). No HTMX interaction is added in L2 (the interactions listed by the spec belong to the features of L3+).
- Ruff (`make lint`), coverage gate 85 % (`make test`), Bandit `-ll` clean, `make i18n-check`, and from Task 1 on `make assets-check`.
- Tests: pytest + pytest-django on real PostgreSQL (`config.settings.test`); browser tests are marked `a11y` and excluded from `make test` (`-m "not a11y"`), run by `make test-a11y`.

### Task 2: Layouts and role-adapted navigation

**Files:**
- Create: `src/core/navigation.py`, `src/core/templatetags/__init__.py` (if missing), `src/core/templatetags/navigation_tags.py`, `src/core/templates/base_minimal.html`, `src/core/templates/components/navbar.html`, `src/core/templates/components/user_menu.html`, `src/core/templates/components/messages.html`, `src/core/tests/test_navigation.py`
- Modify: `src/core/templates/base.html`, `src/core/templates/components/language_switcher.html`, `src/config/settings/base.py` (only if a context processor is needed), `src/locale/fr/LC_MESSAGES/django.po`
- Delete: `src/core/static/core/app.css` once nothing references it (grep templates)

**Interfaces (Produces):**
- `core.navigation.NavItem` (frozen dataclass): `key: str`, `label` (lazy translated), `url_name: str`, `icon: str` (Bootstrap Icons name), `order: int`, `is_visible: Callable[[user], bool]`, `active_prefixes: tuple[str, ...]` (URL path prefixes that mark the item as current; default the item's own URL).
- `core.navigation.register(item: NavItem) -> None` (duplicate key → `ValueError`), `core.navigation.items_for(request) -> list[NavItem-like]` returning the visible items in order, each with resolved `url` and `is_current`. An item whose `url_name` does not resolve is skipped (no error), which is how future entries stay hidden until their package ships.
- Built-in registrations (from each owning app's `AppConfig.ready()`, not from `core`): `home` (core, everyone authenticated), `manage_users` "Administration" (accounts, `can_manage_users`), `audit_log` "Audit log" (audit, `can_view_audit_log`).
- Template tag `{% main_navigation as nav_items %}` (or an inclusion tag) used by `navbar.html`.
- `base.html` blocks kept: `title`, `extra_head`, `content`, `usernav` is replaced by the navbar (grep for templates overriding `usernav` and adapt them). New optional blocks: `breadcrumb`, `page_header`.

**Layout requirements:**
- `base.html`: skip link → `header` with a Bootstrap navbar: brand (logo + "Communities") linking home; on ≥ lg screens the items inline; below lg a toggler button (`aria-controls`, `aria-expanded`, visible label "Menu") opening an **offcanvas** side menu containing the same items (one rendering, responsive via `navbar-expand-lg` + `offcanvas-lg`, not two copies of the list). Current item has `aria-current="page"`. Right side: language switcher (compact select + submit; no auto-submit without JS) and, for authenticated users, the user menu dropdown (avatar initials + name; items My profile, Preferences, My data (data export), Sign out as a POST form button). Anonymous visitors see brand + language switcher + "Sign in" link only.
- Messages: `components/messages.html` renders Django messages as Bootstrap toasts in a fixed container with `aria-live="polite"` (`role="alert"`/`aria-live="assertive"` for error level), visible without JavaScript (`.show`), with a close button labelled "Close"; Bootstrap JS hides them after 8 s only when the user has not focused them (small `core/static/core/js/app.js` loaded with `defer`, included in the asset build or served as a plain static file).
- `main#main` (`tabindex="-1"`) inside a `.container`; `footer` holds a short line "Communities — internal platform" and nothing interactive.
- `base_minimal.html`: same head, skip link, brand header (no navigation items), language switcher, messages, centred narrow `main`. Used later by sign-in and error pages (Task 4).
- Scripts at the end of `body` with `defer`: `dist/bootstrap.bundle.min.js`, `dist/htmx.min.js`, `js/app.js`. Stylesheet `dist/app.css`. `<meta name="color-scheme" content="light dark">`.

**Acceptance Criteria (HTTP tests in `test_navigation.py`):**
- Employee: navbar contains Home and the user menu, not Administration nor Audit log. Functional admin (verified MFA session, reuse the existing helpers): Administration shown. Auditor: Audit log shown, Administration not. Anonymous: no user menu and a Sign in link (test the navbar include directly with a `RequestFactory` request and `AnonymousUser`, since the login page moves to `base_minimal` in Task 4).
- `register` rejects a duplicate key; an item with an unresolvable `url_name` is not rendered.
- `aria-current="page"` is on the current item only (e.g. on `/audit/` for an auditor).
- The page has exactly one `<header>`, one `<main id="main">`, one `<footer>`, every `<nav>` has an `aria-label`, the skip link is the first link in `<body>`.
- A success message renders inside an `aria-live` region; an error message uses `role="alert"`.
- Rendering in French shows translated navigation labels.
- `make lint`, `make test`, `make i18n-check`, `make assets-check` pass.
